GUIDE: HOW TO USE YOUR FRIEND'S HOSTING FOR FILE STORAGE IN FLUTTER

Since Firebase Realtime Database is meant strictly for storing JSON (text) data, trying to push physical files like PDFs, ZIPs, or PPTXs into it will cause severe performance issues and storage limits. While Firebase Cloud Storage is standard, using your friend's web hosting is a completely viable and cost-effective alternative!

This guide will teach you how to treat their hosting as a "File Server" while still using Firebase to store your database text (like titles, subjects, and uploader IDs).

---

### STEP 1: PREPARE THE HOSTING (FRIEND'S SIDE)
1. Ask your friend to create a dedicated folder on their server for your app (e.g., `public_html/linkup_uploads/`).
2. Inside that folder, they need to create another folder specifically for the files called `files/` and make sure it has write permissions (chmod 755 or 777).
3. They need to create a simple PHP script named `upload.php` to handle the incoming files.

---

### STEP 2: THE PHP UPLOAD SCRIPT
Give this exact PHP code to your friend to paste inside the `upload.php` file:

```php
<?php
header('Access-Control-Allow-Origin: *');
header('Content-Type: application/json');

if ($_SERVER['REQUEST_METHOD'] === 'POST' && isset($_FILES['file'])) {
    $uploadDir = 'files/'; 
    
    // Generate a unique filename using timestamp to prevent overwriting
    $fileName = time() . '_' . preg_replace("/[^a-zA-Z0-9.\-_]/", "", basename($_FILES['file']['name']));
    $targetFilePath = $uploadDir . $fileName;
    
    if (move_uploaded_file($_FILES['file']['tmp_name'], $targetFilePath)) {
        // Return the public URL of the uploaded file
        // Make sure to change 'yourfriendsdomain.com' to their actual website!
        $publicUrl = "https://yourfriendsdomain.com/linkup_uploads/" . $targetFilePath;
        echo json_encode(["status" => "success", "url" => $publicUrl]);
    } else {
        http_response_code(500);
        echo json_encode(["status" => "error", "message" => "Upload failed on the server."]);
    }
} else {
    http_response_code(400);
    echo json_encode(["status" => "error", "message" => "No file was sent."]);
}
?>
```

---

### STEP 3: UPDATE YOUR FLUTTER APP
Instead of using `FirebaseStorage.instance.ref()`, you will now send the file to your friend's server via a standard HTTP POST request using the `dio` package you already have installed.

Add this method into your `FirebaseService` (or create a new `StorageService`):

```dart
import 'package:dio/dio.dart';
import 'dart:io';

Future<String> uploadFileToFriendServer(File file) async {
  try {
    // 1. Prepare the file data
    FormData formData = FormData.fromMap({
      "file": await MultipartFile.fromFile(
        file.path, 
        filename: file.path.split('/').last
      ),
    });
    
    // 2. Send the file to your friend's upload.php script
    Response response = await Dio().post(
      "https://yourfriendsdomain.com/linkup_uploads/upload.php", // REPLACE WITH REAL URL
      data: formData,
      options: Options(
        // Allow it to take time for large PDFs
        sendTimeout: const Duration(minutes: 5), 
        receiveTimeout: const Duration(minutes: 5),
      )
    );
    
    // 3. Extract the safe public URL given back by the server
    if (response.data['status'] == 'success') {
      return response.data['url']; 
    } else {
      throw Exception("Server rejected the file.");
    }
  } catch (e) {
    throw Exception('Failed to upload to friend\'s server: $e');
  }
}
```

---

### STEP 4: SAVE THE URL TO FIREBASE 
Once `uploadFileToFriendServer()` finishes, it will return a simple string URL (e.g., `"https://friendsdomain.com/linkup_uploads/files/1684930_math.pdf"`).

1. Take that URL string.
2. Put it into your `ResourceModel` inside the `fileUrl` property.
3. Push that `ResourceModel` to your Firebase Realtime Database exactly like you normally do!

**Result:** Your Firebase Realtime Database stays clean, fast, and lightweight because it only holds text URLs, while your friend's server handles all the heavy lifting of storing the actual gigabytes of PDF and ZIP files!
